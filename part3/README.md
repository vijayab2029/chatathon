# Part 3 — Correlation & Individual Insight Engine

> ## ALL DATA IS SYNTHETIC
> Nothing in this project reads a real calendar, a real person, or a real
> wearable. Every input is generated by `part3/contracts/make_fixtures.py`, and
> every payload we emit carries `"synthetic": true` and
> `"data_provenance": "SIMULATED"`. Keep those labels visible in any UI built on
> top of this.

Part 3 joins Part 1's daily stress scores to Part 2's calendar features, then
finds — per person — which calendar shapes precede a stress spike. The design
commitment is one line: **Gemini agents propose and explain; Python proves.**
The LLM never produces a number. It emits hypotheses in a tiny DSL
(`feature op threshold @ lag`), and `validator.py` computes lift, Pearson r, and
a 1000-iteration permutation p-value in plain Python. What that buys us: a
hallucinated pattern is *harmless*, because a hypothesis that fails validation
never reaches the narrator; and when a judge asks "how do you know that?", the
answer is an arithmetic one we can show on screen. It also means the whole thing
still works with the API key removed — see `--offline`.

## THE PRIVACY CONTRACT

| | `data/out/employee_insight.json` | `data/out/team_correlations.json` |
| --- | --- | --- |
| Unit of record | one **person** | one **pattern** |
| `person_id` | **yes, by design** | **never — not at any nesting depth** |
| Contains | stress trend, top validated patterns with full evidence, insight text, suggested action, critic log | feature/operator/threshold, `n_people_affected`, mean & max lift, severity band, employer-safe `calendar_fact` |
| Gated? | n/a | **No. `gating_applied: false`.** Part 4 owns the k>=5 floor. |
| Audience | that employee only (Part 5) | Part 4 → employer view |

The team file is built by **aggregating across people**
(`emit.aggregate_team_patterns`), never by concatenating individual insights —
concatenating individual insights would let a manager re-identify people from
calendar specifics ("the one with the 07:30 external call on Tuesday"), turning
an anonymised team signal back into surveillance of a named employee. Person ids
enter `aggregate_team_patterns` only as dict keys, used to count *distinct*
people, and are dropped before any `TeamPattern` is constructed.

Part 3 hands Part 4 **honest counts, including counts below the k floor**.
Suppression is policy; policy is Part 4's job. One module owns analytics, one
owns policy. `part3/tests/test_privacy.py` enforces all of this.

## The 4-agent pipeline

```
 stress_scores.csv (P1) ─┐
                         ├─► loaders ─► per-person-per-day feature vector
 meeting_features.json ──┘                          │
 (P2)                                               ▼
                       ┌───────────────────────────────────────────┐
                  A1   │ HYPOTHESISE  (Gemini + always-on baseline)│
                       │ emits DSL objects only, never prose       │
                       └───────────────────────┬───────────────────┘
                                               ▼
                       ┌───────────────────────────────────────────┐
                  A2   │ VALIDATE   ** PURE PYTHON, NO LLM **      │
                       │ THE INTEGRITY GATE                        │
                       │ lift · Pearson r · permutation p · support│
                       │ reject if n_exposed < 3 or p > 0.1        │
                       └───────────────────────┬───────────────────┘
                                               ▼ survivors only
                       ┌───────────────────────────────────────────┐
                  A3   │ NARRATE  (Gemini; templates when offline) │
                       │ sees ONLY validated stats                 │
                       └───────────────────────┬───────────────────┘
                                               ▼
                       ┌───────────────────────────────────────────┐
                  A4   │ CRITIQUE (deterministic rules + Gemini)   │
                       │ no diagnosis · no blame · no unsupported  │
                       │ numbers — always runs, even with no key   │
                       └───────────────────────┬───────────────────┘
                                               ▼
                employee_insight.json   +   team_correlations.json
```

**A2 is the integrity gate.** Everything upstream of it is a suggestion;
everything downstream of it is arithmetic that already happened. A4 also runs
its deterministic half with no API key, because a safety control must not depend
on a quota.

## Setup

```bash
pip install -r part3/requirements.txt
cp part3/.env.example part3/.env      # then put your real GEMINI_API_KEY in it
```

`part3/.env` is gitignored; the key is never printed. Everything except
FastAPI / uvicorn / pytest is stdlib by design — no `requests`, no
`google-generativeai`, no scipy.

## Run it

All commands below are run **from the repo root** unless stated otherwise.

```bash
# regenerate the synthetic fixtures (deterministic seed -> identical output)
python part3/contracts/make_fixtures.py --people 12 --days 28
#   -> part3/data/fixtures/{stress_scores.csv,meeting_features.json,_ground_truth.json}

# run the pipeline with ZERO LLM calls (safest demo path)
cd part3/src && python -m insight.pipeline --offline

# run it with the Gemini agents enabled
cd part3/src && python -m insight.pipeline

# useful flags: --limit 3   --out ../data/out   --stress PATH   --meetings PATH

# serve it
uvicorn api.main:app --reload --port 8000 --app-dir part3

# tests
python -m pytest part3/tests/ -q
```

> Run the pipeline as a **module** (`python -m insight.pipeline` from
> `part3/src`), not as a script path. `python part3/src/insight/pipeline.py`
> currently dies with `ImportError: attempted relative import with no known
> parent package`.

Both output files land in `part3/data/out/`. If the server misbehaves near the
deadline, Part 5 can read those two files straight off disk.

### API

| endpoint | does |
| --- | --- |
| `GET /health` | `{"status":"ok","data_provenance":"SIMULATED"}` |
| `POST /analyze` | body `{"offline": true, "limit": null}` — runs the pipeline over the fixtures, writes both files, returns a summary (`n_people`, `n_patterns_found`, `llm_calls`, `cache_hits`, …) |
| `GET /people` | `{"count": 12, "people": ["emp_001", …]}` — for Part 5's picker |
| `GET /employee/{person_id}` | that person's private insight; 404 if unknown |
| `GET /team/correlations` | the whole team file; Part 4 consumes this |

Read endpoints return **409** if the outputs don't exist yet — POST `/analyze`
first. Errors come back as a 500 with the message and traceback, deliberately
visible for the demo. CORS is wide open so Part 5's UI can call it from
anywhere.

```bash
curl localhost:8000/health
curl -X POST localhost:8000/analyze -H "Content-Type: application/json" -d '{"offline":true}'
curl localhost:8000/people
curl localhost:8000/employee/emp_001
curl localhost:8000/team/correlations
```

`<3 minimal · <7 low · <12 moderate · <20 elevated · else high`.

## For Part 4 (employer aggregation)

Consume **`part3/data/out/team_correlations.json`** only — or
`GET /team/correlations`. Never read `employee_insight.json`; it is private.

You own the k-anonymity policy. We ship `gating_applied: false` and real counts,
*including patterns where `n_people_affected < 5`*. Filter or suppress those
before anything reaches a manager, then flip your own gating flag. `calendar_fact`
is pre-written to be safe to surface verbatim.

## For Part 5 (employee UI)

Consume **`part3/data/out/employee_insight.json`**, or
`GET /people` → `GET /employee/{person_id}`. Show a person **only their own
record**. `stress_trend` is the chart series, `top_patterns` the evidence table,
`insight_text` + `suggested_action` the narrative, and `critic_log` is a nice
demo touch — it shows a rejected narration beside its approved replacement.
Render the `data_provenance: "SIMULATED"` label; it is on every object and every
API response so you never have to special-case it.

## Gemini free tier, rate limits, and `--offline`

Free-tier `gemini-2.5-flash` allows roughly **10 requests/minute and 250/day**,
and a full online run costs ~15 calls *per person* (A1 + A3 + A4). Twelve people
will exhaust a daily quota fast. Three safeguards:

1. **Disk cache** at `.llm_cache/`, keyed on `sha256(model + prompt)`. Re-running
   the same demo costs zero new calls — the summary reports `cache_hits`.
2. **Baseline hypotheses always run**, so the statistical layer is fully
   functional with no LLM at all.
3. **Fallback chain:** `gemini-2.5-flash` → exponential backoff on 429 →
   `gemini-2.5-flash-lite` → deterministic templates. Concurrency is capped by a
   semaphore.

**`--offline` (or `POST /analyze {"offline": true}`) forces the template path and
makes zero network calls.** The numbers are identical either way — only the
prose changes — so it is the right setting for a judged demo on flaky wifi.
`part3/tests/test_integration.py` asserts `llm_calls == 0` in offline mode.
